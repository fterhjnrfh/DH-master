## 2. 术语

- **原始层**：以 block / segment 为单位保存和读取原始样本的层。
- **预览层**：以包络线降采样为核心、为显示提供多级数据的层。
- **查询层**：统一接收窗口请求、返回统一快照的层。
- **快照**：查询层返回给 UI 的不可变结果对象。
- **版本**：用于 UI 判断数据是否更新的单调递增标识。
- **时间轴语义**：对 UI 可见的唯一时间窗口口径。

## 3. 必须冻结的接口

### 3.1 `ICurveQueryService`

职责：

- 统一提供按时间窗查询曲线数据的能力
- 屏蔽实时链与回放链的底层差异

建议定义：

```csharp
public interface ICurveQueryService
{
    ValueTask<CurveWindowSnapshot> QueryAsync(
        PreviewReadRequest request,
        CancellationToken ct = default);
}
```

输入要求：

- `PreviewReadRequest` 必须完整提供时间窗、通道集合、预览层级和结果约束。

输出要求：

- 必须返回 `CurveWindowSnapshot`
- 不允许返回裸点数组

### 3.2 `ICurveFrameProvider`

职责：

- 给 UI 提供“最新版本”拉取入口
- 用于替代直接响应每次数据更新事件

建议定义：

```csharp
public interface ICurveFrameProvider
{
    CurveFrameVersion GetLatestVersion(Guid sessionId);

    ValueTask<CurveWindowSnapshot> GetLatestAsync(
        PreviewReadRequest request,
        CancellationToken ct = default);
}
```

输入要求：

- `sessionId` 必须是稳定会话标识
- `request` 必须与 `ICurveQueryService` 使用同一请求模型

输出要求：

- `GetLatestVersion` 必须只返回最新版本信息，不包含数据体
- `GetLatestAsync` 必须返回快照

### 3.3 `IRawSegmentReader`

职责：

- 从原始存储层按范围读取原始段数据

建议定义：

```csharp
public interface IRawSegmentReader
{
    ValueTask<RawSegmentReadResult> ReadAsync(
        RawReadRequest request,
        CancellationToken ct = default);
}
```

输入要求：

- `RawReadRequest` 必须支持按 `Session + Segment + TimeRange + ChannelSet` 读取

输出要求：

- 结果必须表达 segment 范围
- 结果不得直接假定用于 UI 绘制

### 3.4 `IDataSessionCatalog`

职责：

- 加载会话级元数据
- 快速列出 segment、source、channel 范围

建议定义：

```csharp
public interface IDataSessionCatalog
{
    ValueTask<SessionDescriptor> OpenAsync(string sessionPath, CancellationToken ct = default);
}
```

## 4. 必须冻结的对象模型

### 4.1 `SessionDescriptor`

最低字段：

- `SessionId`
- `TaskName`
- `StartTime`
- `EndTime`
- `StorageFormat`
- `Recovered`
- `Sources`
- `PreviewLevels`

补充要求：

- `StorageFormat` 只表达底层格式，不表达显示策略
- `PreviewLevels` 只表达可用层级，不表达具体构建实现

#### 字段定义表

| 字段名 | 类型 | 必填 | 说明 | 来源 |
| --- | --- | --- | --- | --- |
| `SessionId` | `Guid` | 是 | 会话唯一标识 | Session / Manifest |
| `TaskName` | `string` | 是 | 任务名称 | Session |
| `StartTime` | `DateTimeOffset` | 是 | 会话开始时间 | Session / Manifest |
| `EndTime` | `DateTimeOffset?` | 否 | 会话结束时间 | Session / Manifest |
| `StorageFormat` | `string` / enum | 是 | 底层存储格式 | Manifest |
| `Recovered` | `bool` | 是 | 是否为恢复会话 | Manifest / Recovery |
| `Sources` | `IReadOnlyList<SourceDescriptor>` | 是 | 会话内 source 列表 | Catalog |
| `PreviewLevels` | `IReadOnlyList<string>` / enum list | 是 | 当前会话可用预览层级 | Preview Metadata |

### 4.2 `SourceDescriptor`

最低字段：

- `SourceId`
- `DeviceName`
- `ChannelCount`
- `SampleRateHz`
- `TimeAxisKind`

#### 字段定义表

| 字段名 | 类型 | 必填 | 说明 | 来源 |
| --- | --- | --- | --- | --- |
| `SourceId` | `int` | 是 | Source 标识 | Session / Catalog |
| `DeviceName` | `string` | 是 | 设备名称或逻辑源名称 | Session / Catalog |
| `ChannelCount` | `int` | 是 | Source 通道数 | Session / Catalog |
| `SampleRateHz` | `double` | 是 | 采样率 | Source Metadata |
| `TimeAxisKind` | `string` / enum | 是 | UI 可见时间轴语义 | Query Layer |

#### 字段定义表

| 字段名 | 类型 | 必填 | 说明 | 来源 |

### 4.4 `PreviewReadRequest`

#### 字段定义表

| `ChannelIds` | `IReadOnlyList<int>` | 是 | 指定通道集合 |

| `WindowEnd` | `double` / `DateTimeOffset` | 是 | 窗口终点 |
| `PreviewLevel` | `string` / enum | 是 | 预览层级 |
| `MaxPointsPerChannel` | `int` | 是 | 每通道返回点数预算 |
| `RequireEnvelopeSemantics` | `bool` | 是 | 是否强制包络语义 |
| `PreferredTimeAxisKind` | `string` / enum | 否 | 希望采用的时间轴口径 |
| `AllowDegradedResult` | `bool` | 是 | 是否允许降级结果 |
| `RequireCompleteWindow` | `bool` | 是 | 是否要求完整覆盖窗口 |

## 5. 时间轴与版本语义

### 5.1 时间轴语义

本阶段必须冻结以下原则：

1. UI 只能看到一套统一时间轴语义。
2. 底层可以同时保存：
   - `StartSampleIndex`
   - `DeviceTimestampNs`
   - `HostTimestampNs`
3. 查询层必须统一映射到：
   - `WindowStart`
   - `WindowEnd`
   - `TimeAxisKind`

### 5.2 版本语义

本阶段必须冻结以下原则：

1. `Version` 只表达窗口数据版本
2. `DataEpoch` 表达时间轴纪元变化
3. `SourceVersion` 表达底层数据源变化

## 8.1 必须冻结的状态枚举

### `PreviewLevel`

| 值 | 含义 | 备注 |
| --- | --- | --- |
| `L0` | 原始层，不降采样 | 用于单视图精查 |
| `L1` | 单视图高保真预览 | 用于单视图实时与快速回放 |
| `L2` | 多视图总览预览 | 用于 `16/64` 视图总览 |

### `BuildState`

| 值 | 含义 |
| --- | --- |
| `Ready` | 结果完整可用 |
| `Building` | 结果正在构建 |
| `Degraded` | 当前结果可用但非最佳层级 |
| `Missing` | 当前请求无法返回结果 |

## 9.1.1 统一日志落盘规则

本阶段开始，后续所有架构验证统一采用以下落盘规则：

- 根目录：`data/architecture-validation/`
- 阶段目录：`phase1/`、`phase2/`、`phase3/`、`phase4/`
- 轮次目录：`yyyyMMdd-HHmmss/`

每轮最少包含：

- `summary.log`
  - 记录本轮目标、基线、是否通过
- `validation.log`
  - 记录人工验证步骤与结果
- `query.log`
  - 记录查询层相关日志；本阶段可为空占位

要求：

1. 同一轮的所有日志必须落在同一时间戳目录。
2. 每轮必须在 `summary.log` 写明：
   - `phase`
   - `baseline`
   - `scenarios`
   - `result`
3. 后续阶段不得各自发明新的日志目录层级。
