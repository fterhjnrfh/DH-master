## 1. 目标

这组文档用于把当前的大架构拆成可落地的阶段，避免：

- 一次性大改导致回归不可控
- 显示侧、存储侧、回放侧各做一套
- 后续合并时缺少边界和冻结点

## 1.1 当前验收口径

当前主线必须统一以下验收定义：

1. 帧率底线：
   - `1V-64C >= 80 FPS`
   - `64V-64C >= 60 FPS`
2. `4000` 表示“每条曲线真实点数规模进入验收区间”的参考口径，不表示“显示上限”。
3. 不允许通过把单条曲线先压到 `4000` 点以内来换取验收达标。
4. 所有阶段实现都必须同时满足：
   - 包络异常值保真
   - `5ms / 200Hz` 设计目标
   - `64` 个独立视图不合并
   - 实际点数超过 `4000` 后仍继续正常推进显示

## 3. 阶段推进原则

1. 每个阶段只替换一层主链路，不同时改多层。
2. 每个阶段结束后都必须留下可回退边界。
3. 旧链路可以短期兼容，但不能长期双轨运行。
4. 包络线异常保真、`5ms / 200Hz` 目标、`64` 个独立视图，这三条贯穿所有阶段。

### 4.1 当前主线约束

1. 后续推进以新架构主线为准，不再继续扩展旧结果页链路。
2. 旧链路只保当前可用基线，不再作为主要演进方向。
3. 新架构推进期间，性能指标不得低于当前批准基线。
4. 任何新阶段代码默认不得直接切入 UI 主链，除非通过独立验证和显式开关验证。
5. Phase 4 接入 UI 前必须先完成架构守门：确认实时链不读文件、回放链不整通道读文件、`4000` 不作为硬上限、日志能区分新旧链路。
6. 实时录制与实时绘制必须同时成立：采集/落盘为高优先级链路，绘制只能作为低优先级、可降级、可丢中间预览帧的消费者。
7. 当前统一数据根目录默认解析为工程根目录下的 `data`；如需指定到本机高速盘，设置 `DH_DATA_ROOT`。采集产物、TDMS 直写 session、preview/raw index、architecture-validation 与 performance 日志默认都应通过 `AppDataPaths` 解析，避免因启动目录变化写入 `bin\data` 或旧机器路径。
8. 当前高速采集主线的实际原始文件格式为物理 source-sharded `.tdms` 分段，`.dhseg` 仅保留为历史/诊断过渡格式。preview sidecar 不在采集热路径同步生成，默认录后或后台构建。
