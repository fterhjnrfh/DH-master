## 3. 本阶段新增层

### 3.1 `Preview Layer`

职责：

- 构建 `L0/L1/L2` 多级预览
- 统一实现包络线降采样
- 为实时显示和回放查询提供统一预览来源

必须满足：

- `L0/L1/L2` 层级清晰
- 同一层级跨实时链和历史链语义一致

### 3.2 `Query Layer`

职责：

- 接收窗口请求
- 决定读原始层还是预览层
- 返回统一 `CurveWindowSnapshot`

#### Query 输入输出约束表

| 项目 | 约束 |
| --- | --- |
| 输入模型 | 只能使用 Phase 1 冻结的 `PreviewReadRequest` |
| 输出模型 | 只能返回 `CurveWindowSnapshot` |
| 时间轴 | 必须遵循统一时间轴语义 |
| 状态字段 | 必须正确填充 `IsPreview / IsComplete / BuildState / TimeAxisKind` |

## 4. 预览层构建策略

### 4.1 同步构建

适用：

- 最近窗口
- 实时显示需要的轻量预览层

要求：

- 成本必须可控
- 不阻塞 SDK callback
- 不阻塞原始写盘

| 项目 | 说明 |
| --- | --- |
| 输入 | 最近窗口原始块 |
| 输出 | 运行期预览缓存 |
| 允许场景 | 实时最近窗口 |
| 禁止场景 | 历史整会话全量构建 |

### 4.2 异步增量构建

适用：

- 历史会话预览层补齐
- 长时间后台整理

| 项目 | 说明 |
| --- | --- |
| 输入 | 已落盘 segment |
| 输出 | 持久化预览文件 |
| 触发时机 | 后台任务 |
| 禁止影响 | 不得阻塞写盘主链路 |

### 4.3 懒构建

适用：

- 历史首次打开但对应预览层不存在

要求：

- 仅对所请求 window 相关 segment 局部构建
- 不允许首次打开就全会话重建

| 项目 | 说明 |
| --- | --- |
| 输入 | 历史查询请求 |
| 输出 | 局部预览结果 |
| 触发时机 | 缺失预览文件时 |
| 禁止行为 | 全会话重建 |

## 5. 包络线降采样统一原则

本阶段必须明确：

1. 所有降采样统一走同一套包络实现
2. 不允许不同控件各自维护私有降采样逻辑
3. 不允许简单均值替代 bucket 代表值
4. 多级预览文件与运行期缓存必须遵守同一套包络语义

### 5.2 与验收点数指标的关系

本阶段必须明确：

1. `4000` 不是预览层的固定显示上限。
2. `L1/L2` 的存在目的，是在真实点数高于 `4000` 时仍维持可用显示与可用性能。
3. 预览层可以按层级控制代表点密度，但不得把“代表点数”伪装成“真实点数”。
4. 预览层的任何优化都不得改变验收语义：
   - 单条曲线真实点数超过 `4000` 时，仍必须按真实进度推进
   - 异常值仍必须可见

### 5.1 包络实现最低要求表

| 项目 | 最低要求 |
| --- | --- |
| bucket 代表值 | 不允许简单均值 |
| 极值保留 | 必须保 `min/max` |
| 时间顺序 | 输出点必须单调按时间排列 |
| 去重 | 可以去重，但不得破坏异常边沿 |
| 层级一致性 | `L1/L2/...` 统一语义 |

---

## 6. 与旧链路的关系

本阶段允许：

- 旧链路继续存在
- 新链路并行验证

但要求：

1. 同一个视图不能同时使用两套数据链
2. 新链路一旦稳定覆盖某类场景，旧链路必须退到兼容层
3. 不允许继续在旧链路上增加新的核心逻辑

---

## 7. 优先替换场景

建议优先让新链路先覆盖：

1. 单视图最近窗口查询
2. 多视图最近窗口查询
3. 历史会话快速打开的概览查询

不建议一开始就覆盖：

- 全量历史原始读取
- 所有高级交互场景

---

## 8. 交付物

1. Query Layer 最小实现
2. Preview Layer 最小实现
3. 包络线降采样统一实现
4. 迁移场景清单

## 8.1 验收输入输出表

| 验收项 | 输入 | 输出 |
| --- | --- | --- |
| 查询层最小实现 | `PreviewReadRequest` | 合规 `CurveWindowSnapshot` |
| 预览层最小实现 | 最近原始块 / segment | `L1/L2` 预览结果 |
| 包络统一实现 | 任意降采样请求 | 不丢异常值的结果 |
| UI 首批迁移 | 单视图 / 多视图最近窗口 | 通过查询层完成绘制 |

---

## 9. 阶段验收标准

1. 查询层可返回统一 `CurveWindowSnapshot`
2. 运行期预览缓存可被查询层消费
3. 包络线降采样实现被统一收口
4. UI 至少有一部分场景已改为读取查询层
5. 阶段内任何实验性实现不得把 `4000` 解释成“每条曲线最多只显示 `4000` 点”

## 9.2 人工验证要求

本阶段至少覆盖以下人工测试场景：

1. `1V-64C` 最近窗口查询
2. `64V-16C` 最近窗口查询
3. `64V-64C` 最近窗口查询
4. 单曲线与多曲线切换
5. 预览缺失时懒构建

每个场景至少验证：

- 是否返回正确 `previewLevel`
- 是否返回正确 `buildState`
- 包络线异常值是否仍可见

## 9.3 量化退出门槛

本阶段通过标准：

1. `ICurveQueryService` 在目标场景下可稳定返回 `CurveWindowSnapshot`。
2. `previewLevel`、`buildState`、`isPreview`、`isComplete` 字段填充正确率达到 `100%`。
3. 在已迁移场景下，显示语义不得回退：
   - sweep 语义不变
   - 单曲线与多曲线显示语义不变
   - 包络异常值不丢
4. 查询链路接入后的代表性场景帧率相对当前批准基线不得回退超过 `5%`。
5. 首批迁移场景日志完整落盘。

## 9.4 旧链路退场清单

本阶段应开始冻结以下旧路径，不再新增功能：

- `CurvePanel` 内部新增数据裁剪逻辑
- `RealtimeDisplayCache` 新增显示策略逻辑
- `DataBus` 新增 UI 专用预览策略

允许保留：

- 兼容调用
- 对照验证

不允许保留：

- 新功能继续挂旧链路

---

## 10. 结论

Phase 2 的核心不是“把所有旧代码删掉”，而是：

**让新的查询层和预览层先真正跑起来，并开始接管数据访问逻辑。**
